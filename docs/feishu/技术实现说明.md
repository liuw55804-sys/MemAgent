# MemAgent 技术实现说明

> 当前版本：v0.34  
> 定位：面向 Codex 等 Coding Agent 的、本地优先的工作流记忆层。

## 1. 解决的问题

Coding Agent 的会话天然易断：同一个项目换一个 Codex task 后，已经验证过的
工具入口、排查顺序和个人开发偏好很容易丢失。MemAgent 把这些经验保存成小而明确
的本地记忆卡片，并在新任务开始时按项目召回一段短上下文。

它不是替代 Coding Agent 的通用助手，也不是自动执行业务操作的后台 Agent。它负责
让 Agent 少重复寻找已经走通的路径。

## 2. 系统架构

<whiteboard type="blank"></whiteboard>

核心模块：

- **用户级 Codex Skill**：安装在 `~/.codex/skills/memagent/`，不修改业务仓库。
- **Process Router**：把自然语言路由为 recall、草稿、确认保存、反馈、handoff 或 none。
- **Memory Store**：在 `~/.memagent/` 保存记忆卡、待确认草稿、召回 trace 与活动证据。
- **Recall Engine**：按 cwd、Git root 等项目上下文过滤，用 BM25/关键词排序并压缩为短提示。
- **LLM Quality Gate（v0.34）**：只在草稿质量判断中按需调用兼容 OpenAI API；不参与每轮普通开发对话。
- **Activity Report**：把“召回 -> 反馈”“草稿 -> 确认保存 -> 后续复用”聚合成项目级活动报告。

## 3. 一次记忆交互的时序

1. 用户在 Codex 中自然表达任务或经验，例如“把这个习惯记住，先给我预览”。
2. User Skill 调用 `memagent process`，Router 在本地识别意图。
3. 对 recall，系统只取与当前项目相关的少量记忆，作为提示而非事实来源。
4. 对 draft，系统先生成本地草稿；只有偏好、决策、流程或低置信候选才可能进入 LLM Quality Gate。
5. 预览永远不会直接写长期记忆。只有用户说“确认保存”后，pending draft 才被写入 memory card。
6. 后续召回与“这条有用/不相关”等自然语言反馈会写入本地 evidence，供 activity 复盘。

## 4. v0.34：LLM 质量门

### 4.1 为什么需要它

早期 heuristic 更容易识别命令、数据库入口和报错路径，但会低估这类同样有价值的经验：

> 在某个服务仓库中，默认只修改当前需求相关代码；方案放在个人材料目录。

这是一条稳定、可复用的用户偏好，却可能缺少命令/API/库表等关键词。v0.34 让模型仅在
这类语义判断上辅助分类与打分。

### 4.2 调用条件与输入

满足以下条件才调用一次：用户已经要求生成 memory preview，且候选是 preference、decision、
workflow 或 heuristic 分数处于模糊区间；同时用户在本地显式配置了 provider profile。

发送给模型的是短草稿、抽象后的来源摘要和最小项目上下文。绝不发送完整 Codex transcript、
密码、cookie、私钥、token、原始请求响应或敏感业务样本。绝对路径、URL、疑似密钥、复合标识符
和长数字会先泛化。

### 4.3 输出与回退

模型必须返回严格 JSON：`kind`、`quality_label`、`quality_score`、`reasons` 与一个泛化 rewrite。
模型只给建议，不能决定保存。

若 profile 不存在、请求失败、超时或 JSON 非法，MemAgent 继续输出本地 heuristic 草稿，并标记
`heuristic_fallback`，不会阻塞开发。

## 5. 本地数据与生命周期

所有状态只在 `~/.memagent/`：

- `memories/`：用户确认后的长期记忆卡。
- `pending_memory_drafts/`：当前项目待确认草稿。
- `recall_traces/`：实际召回及用户有用/无用反馈。
- `process_traces/`：有动作的过程证据。

草稿与过程 trace 只保留最小质量门信息（是否调用、是否回退、最终来源、标签和分数），不保存
完整模型响应、LLM rewrite 或草稿来源原文。

## 6. 验证与边界

v0.34 覆盖 mock provider 的 preference 纠偏、非法 JSON/无配置回退、CLI/MCP 传参、pending draft
兼容性，以及无 `AGENTS.md` 的临时 Git 项目端到端流程。全量单测为 114 项。

边界保持不变：不自动写长期记忆；不修改业务仓库、业务 `AGENTS.md` 或业务 Git 工作区；不引入
向量数据库、后台守护进程或通用桌面 Agent。

## 7. 版本演进摘要

- **v0.32**：用户级 Codex Skill，实现业务仓库零侵入。
- **v0.33**：memory lifecycle observability，支持按项目查看草稿、确认、反馈与后续复用。
- **v0.34**：LLM-assisted memory quality gate，补足 preference/decision/workflow 的语义型质量判断。
