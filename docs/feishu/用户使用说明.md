# MemAgent 用户使用说明

> 当前版本：v0.34  
> 适用对象：使用 Codex 进行日常开发、排查和跨会话协作的开发者。

## 1. 它会帮你做什么

MemAgent 记住的是“下次可少走弯路”的开发经验，例如：

- 某类排查优先从哪个工具、实时 schema、调用链进入；
- 某条失败路径为什么不该再走；
- 某个项目里稳定的开发偏好与验证顺序；
- 一个 task 暂停时，下一次继续所需的上下文。

记忆默认按项目隔离，保存在本机 `~/.memagent/`。它不会改业务代码、业务 `AGENTS.md` 或 Git 工作区。

## 2. 日常怎么说

不需要记命令。直接在 Codex 对话里自然表达：

| 你的表达 | MemAgent 的行为 |
| --- | --- |
| “之前这个怎么查？”“按上次的思路继续” | 尝试召回当前项目的短提示 |
| “记住这次踩坑，先给我预览” | 生成草稿，等待确认 |
| “把这个习惯记住” | 把明确的稳定偏好做成待确认草稿 |
| “确认保存” | 保存刚才已预览的草稿 |
| “刚刚那条有用”“不是这个问题” | 给最近一次召回留反馈 |
| “上次做到哪？” | 展示项目 handoff |
| “MemAgent 最近做得怎么样？” | 汇总召回、反馈、草稿和保存情况 |

无关的小改动、普通知识问答和纯机械操作会正常继续，不需要刻意调用 MemAgent。

## 3. 使用闭环

> 使用闭环图已同步至飞书正文；仓库保留 `用户使用闭环图.mmd` 作为可维护图源。

### 场景 A：新会话继续排查

1. 说“之前类似问题怎么查？”
2. Codex 可能给出一小段相关经验，例如先看实时 schema，再检查 DAL/模型/调用链。
3. 把它当作起点，仍以实时代码、数据和工具输出为准。
4. 若确实帮上忙，说“刚刚那条有用”；这会帮助 MemAgent 未来评估召回效果。

### 场景 B：沉淀一次真实经验

1. 任务中走通一条值得复用的路径，或明确一个稳定偏好。
2. 说“记住这个，先给我预览”。
3. 先检查 topic、kind、triggers 和 memory 是否准确。
4. 正确才说“确认保存”。不满意就直接说哪里需要改，再要一个新预览。

预览不等于保存。没有确认，长期记忆卡不会产生。

## 4. 可选：让模型辅助判断草稿质量

默认完全本地运行。对“个人偏好、技术决策、工作流”这类不容易靠关键词判断的经验，可以启用
已配置的 OpenAI-compatible provider。它只在生成 memory preview 时按需调用一次，不会读取或上传
整段 Codex 对话。

启用后，预览会显示以下其中一种来源：

- `llm_assisted`：模型辅助了分类/质量建议；
- `heuristic` 或 `heuristic_skipped`：本地规则足够明确，不需要模型；
- `heuristic_fallback`：模型不可用，已经平稳回退到本地规则。

无论哪种来源，保存权都在你手上。

## 5. 查看效果与清理预期

开发一段时间后，直接问“MemAgent 最近做得怎么样？”。报告会按当前项目展示：召回次数、收到的
有用/无用反馈、草稿数、待确认草稿、已确认保存数，以及部分近期事件。

待确认草稿是正常状态：说明系统等你 review，而不是悄悄把内容写成长期记忆。新的草稿可能替换同一项目
中旧的待确认草稿。

## 6. 使用原则

- 把召回内容当提示，而不是事实；关键结论仍要验证实时来源。
- 本地私有记忆可以保留必要的命令和工程入口，但不要保存 token、cookie、密码、私钥或原始敏感样本。
- 需要对外展示、做简历或公开 demo 时，先泛化公司内部名称和数据。
- `trace eval`、`replay` 是开发者评估工具，普通开发不需要手动运行。
